# 广告 Agent 评测台（Ad Agent Eval Lab）

HenryHwang-AI 的 AI PM 作品集。一个可以离线打开的静态评测台：同一批合成广告任务上，对照三种 Agent 架构能不能产出**可投放**的素材，而不是哪一段文案更顺。

虚构品牌只有三个：**北境咖啡**、**星轨耳机**、**青禾护肤**。页面不调用模型，不需要 API Key。

## 这是什么

评测台把一条广告 Agent 从「演示生成」收成一套可以回归的决定：

- 四条固定简报：新客获客、素材爆款筛选、合规改写、多语言落地页
- 三种架构并排：Baseline（单轮）、Tool-augmented（检索 + 规则）、Multi-step + retrieval（规划、只取有效文档、批评后再改）
- 每条输出上的延迟、token、演示成本、引用覆盖、接地率、幻觉标记、政策结论（通过 / 抽检 / 阻断 / 否决）
- 记分牌：pairwise 胜率、Elo（K=24）、人机偏好。种子票是预写的三角色盲测，你也可以继续投票
- D0 → D1 → D2 的迭代：48 条回归探针上的前后指标，和当天的上线 / 停更决定
- 浏览器内导出 CSV
- 「产品决策」：为什么用这些指标、什么情况杀掉、自动裁判和人各管什么

代表探针、种子偏好票、48 条回归集是三层证据，页面上分开写，避免把一条文案说成大盘。

## 为什么做

广告 Agent 最容易被评成「好不好看」。好看不能决定能不能花媒体预算。这个评测台把上线规则写成字典序：

1. 政策否决先于一切，偏好分不能把违规稿投回去
2. 事实槽位必须对上品牌库里仍然有效的文档
3. 生成类主张要能点回引用
4. 人的盲测只比较已经过线的候选
5. 最后才比延迟和**单条可投放成本**

基线的单次调用更便宜，可投放成本更高，因为废片多。这个区别是评测台想讲清楚的事。

## 怎么运行

需要 Python 3，不需要安装依赖，也不需要构建。

```bash
cd ad-agent-eval-lab
python -m http.server 8000
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。根目录的 `index.html` 就是应用。

数据在 `data.js`，交互在 `app.js`，样式在 `styles.css`。三个文件都由页面按相对路径加载。断网之后，只要页面已经打开过、或者你是在本机起的这个静态服务，评测、投票和导出都不访问外网。

投票记在浏览器的 `localStorage`（键名 `ael-user-votes-v1`）。清除站点数据就会丢掉你追加的票，预写种子票还在 `data.js` 里。

键盘：`1` 到 `4` 切换任务。

## 建议怎么看

1. 先读「新客获客」。基线虚构产地并写出绝对化用语；工具增强引用了已过期的夜航冰杯；多步检索把过期文档丢掉。点青色下划线可以打开品牌库原文，过期文档会标成 `expired`。
2. 切到「素材爆款筛选」。历史 CTR 最高的一条是医疗向素材，金标要求下线。金标不会进入模型输入。
3. 在记分牌里投一张票。默认是盲测（方案甲 / 方案乙）。如果你投给了政策未通过的方案，Elo 会变，否决不撤销。
4. 打开「三日迭代」。D0 触发幻觉率和可投放成本两条线；D2 总体过线，但多语言子集的政策通过率和幻觉率仍然触发停线。
5. 导出 CSV。文件带 UTF-8 BOM，Excel 可以直接打开中文。里面有架构行、投票行，以及三天回归集摘要。

界面尊重 `prefers-reduced-motion`：系统要求减少动态效果时，回放会直接给出完整轨迹，不做逐行延时。

## 它如何证明 AI PM 能力

| 能力 | 在这个评测台里对应什么 |
| --- | --- |
| 问题定义 | 北极星是可投放资产，不是文案相似度，也不是模型自评 |
| 指标设计 | 接地率、引用覆盖、政策通过、幻觉率、pairwise / Elo、单条可投放成本、p95 延迟。每个都写了不选什么 |
| 决策规则 | 字典序，而不是把合规和文采加权成一个分 |
| Kill criteria | 幻觉 > 5%、政策通过 < 95%、p95 > 8s、可投放成本 > ¥0.08。演示数据里这些线真的会触发 |
| 人机分工 | 自动裁判挡硬伤；投放、品牌、合规三角色盲测，且不能推翻否决 |
| 证据分层 | 代表探针、小样本偏好票、48 条回归集分开引用。种子票 n=8，页面写明达不到 n≥200 的架构判决 |
| 迭代与取舍 | D0 不放量，D1 不自动投放，D2 分流上线。多语言失败时补术语表，不换掉整套架构 |
| 降级手册 | 延迟失守时，只有筛选任务可以退回工具增强，而且只能排序、不能放行 |
| 可演示 | 离线、无密钥、合成数据、结果可导出，面试时可以当场走完一条决定 |

## 数据与边界

- 品牌、渠道（流光信息流、栖息社区）、价格和功效边界都是为评测编写的，不代表任何在营商品或广告平台
- 成本是按架构复杂度分档的演示数字，不是某一家模型的账单
- Elo 与投票顺序有关。种子票的顺序是固定的，你的票按投票时间排在后面
- 回归集的通过率是预先算好的汇总，用来讲三日决策；它不会因为你在竞技场加票而改写
- 自动裁判本身没有再做一层元评测。真要上线，还需要抽检裁判的漏放和误杀
